# Idea Refine: 升级极简手绘流式白板动画引擎 (Whiteboard Stream Animation)

## 1. Problem Statement
**How Might We (我们如何能够)** 在《如何更好地生活》短视频自动化管线中，将原本基于内置预设 SVG 图标的简易白板拼贴，深度升级为类似 `geeklee/srt-whiteboard-animation` 的**「AI 栅格插画 + 字幕驱动语义分区 + 连续流式笔迹（Ink 铺线稿 -> Color 添彩）+ 手部动力学贴合」**高表现力白板手绘引擎，既保持批处理 CLI 的端到端一键出片效率，又赋予短视频极高人情味、高完播率与强叙事同步的白板解说质感？

---

## 2. Recommended Direction
**深度重构升级现有 `src/whiteboard` 模块，构建「端到端自动编排 + 本地交互微调」的双模栅格流式手绘引擎：**

1. **统一前端视觉规范 (`w1_whiteboard`)**：
   - 锁定暖米黄旧纸背景（`#F5EBD7`）、深灰草图线条、克制马卡龙强调色（蓝/橙/红点缀）。
   - 彻底摒弃复杂 3D 质感、杂乱背景与脏污剪报，单幕聚焦 1~2 个核心概念实体，留白率 $\ge 65\%$。
2. **字幕驱动的自动化语义分区 (Autonomous Annotation)**：
   - 基于 `srt_generator.py` 生成的高精度口播时序（每幕 4.0~5.2 秒），结合 LLM 结构化提示词自动预测各主体的空间边界框（`region`）与叙事出场次序（`sequence`）。
   - 引入 OpenCV 连通域与边缘显著性检测作为底层辅助，实现无需人工标记的高可用自动遮罩切分。
3. **连续流式落墨与时序编排 (Stream Ink & Color Reveal)**：
   - 每区域采用流式画法：以 `ink:color = 2:1` 划分时间，前半段沿图像骨架/网格扫描铺陈黑线草图，后半段通过轮廓扫描（Contour-wipe）均匀注入色彩。
   - 严格执行**「允许掩码 = 目标矩形 - 全部后续矩形 - 保护区」**的不变量，确保未讲到的知识点绝对不提前漏线。
4. **轻量交互预览台兜底 (Human-in-the-loop Previewer)**：
   - 提供基于 HTML5 的本地轻量预览台（无需后端服务），创作者若需追求极致精品，可打开界面拖拽调整区域边界与时序后直接保存回写。

## 3. Evaluation & Stress-Test (评估与压力测试)

| 评估维度 | 现状与挑战 | 破局方案与应对策略 |
|---|---|---|
| **用户价值 (User Value)** | 原有静态图文在完播率上容易中途跳出；纯 I2V 视频存在面部或文字扭曲乱码。 | **强行抓眼与心流引导**：白板手绘利用人眼的「预测心理」（观众会本能猜测笔尖下一秒画出什么），天然具有极高的完播率和完播停留时长；同时彻底根绝 AI Slop 幻觉。 |
| **技术可行性 (Feasibility)** | 栅格图像骨架提取与逐帧合成在传统视频管线中容易计算耗时过长。 | **纯 Python/OpenCV/AV 极速管线**：借鉴开源经验，采用多进程/向量化掩码操作与单幕独立渲染，单镜 5 秒视频渲染耗时预期可压缩在 3~8 秒内，完全可承受。 |
| **差异化壁垒 (Differentiation)** | 传统商业白板软件（如 VideoScribe、Doodly）依赖死板图标库，无法画出定制化 AI 概念插画。 | **生图大模型与物理笔迹结合**：既具备生成任意生活概念场景的无限表现力，又拥有机械臂/真人画师般的流式绘制真实感。 |

## 4. Key Assumptions to Validate (待验证的核心假设)
- [ ] **假设 1（生图线稿稳定性）**：生图模型在 `w1_whiteboard` 提示词下，生成的米纸黑线插画具备足够清晰的骨架结构，OpenCV 骨架算法能够稳定提取笔迹轨迹而无严重噪波。
  - *验证方式*：抽取 5 篇典型生活指南条目生图，运行骨架追踪算法并可视化笔迹连通性。
- [ ] **假设 2（免人工自动分区准确度）**：LLM 配合 OpenCV 连通域分析能够达到 $\ge 80\%$ 的自动合理分区率，使得全自动批量出片成为现实。
  - *验证方式*：对比「纯算法自动分区出片」与「人工微调出片」的主观叙事流畅度。
- [ ] **假设 3（性能与吞吐瓶颈）**：在 Windows 本地环境下合成 1080x1920 竖屏 30fps 白板 MP4 切片，单幕耗时不超过 10 秒。
  - *验证方式*：使用 `pyav` 或 `cv2.VideoWriter` 编写基准性能测试脚本。

## 5. MVP Scope (敏捷落地范围)

### ✅ What's IN (第一期重点落地)
1. **统一画风收敛**：删除废弃的 `y2_vox`，所有规则、避坑与机理类条目全面平滑迁移至 `w1_whiteboard`。
2. **核心流式笔迹渲染器**：在 `src/whiteboard/` 中移植吸收 `render_stream_whiteboard` 核心算法（允许掩码扣除、骨架/网格扫描轨迹、ink->color 双阶段绘制、动态笔尖跟随）。
3. **分镜时序自适应对齐**：直接复用系统已有的 `srt_generator.py` 字幕时间戳，将每个分镜的 4~5 秒时长精准映射为绘制节奏。
4. **单分镜与合成测试**：提供独立的 CLI 验证指令与单元测试覆盖。

### ❌ NOT Doing (明确不做的范围及原因)
- **暂不做沉重的 Web 全功能编辑 SaaS 后台**：保持当前项目的轻量极简 CLI 架构，不引入庞大的 React/Vue 全栈依赖；预览台采用单文件原生 HTML5。
- **暂不做复杂的 3D 骨骼手臂或多角度手势动作**：仅使用 2D 拟真金属触控笔/绘图手配合动态柔和阴影，避免 3D 算力消耗与姿态畸变。
- **暂不做物理级水墨渗透扩散模拟**：保持素描线条与极简平涂上色的干净克制美感，规避复杂的流体力学着色器开销。

## 6. Open Questions (待推进决策的开放问题)
1. **竖屏 (9:16) 下的手部尺寸自适应**：原 Skill 主要针对 16:9 横屏，在 9:16 竖屏（1080x1920）构图中，手部素材需要进行适当缩放与笔尖角度偏置，避免手掌过大遮挡文字。
2. **文字与图形的混合层级**：短视频中的核心强调浮现字（Kinetic Typography），是作为独立图层悬浮在白板上方，还是由白板笔以写字轨迹逐笔勾画？（建议前期文字采用干净的动态淡入/浮现，图形部分走流式笔迹）。
