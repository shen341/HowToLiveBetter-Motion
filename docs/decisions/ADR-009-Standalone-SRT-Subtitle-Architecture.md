# ADR-009: 独立外挂 SRT 字幕导出引擎与音频时间轴绝对对齐架构

## 状态 (Status)
**Accepted (已采纳实施)**

## 日期 (Date)
2026-10-11

## 背景与上下文 (Context)
在流水线早期，字幕主要以“硬字幕（Burned-in Subtitles）”形式渲染在下部黄金分割点（$Y \approx 1186\text{px}$）的深色半透明磨砂胶囊中。
在实际创作与平台运营流程中，存在以下核心痛点：
1. **二次精修受限**：硬字幕烧录进视频像素后无法修改。创作者若希望在剪映/CapCut/Premiere 中针对重点关键词标黄、放大重音词或微调个别标点，必须重新渲染整部视频；
2. **多平台软字幕与 SEO 索引**：B站、YouTube、小红书等平台支持上传独立 `.srt` 软字幕，便于搜索引擎抓取全文关键词并提升推荐权重；
3. **播放器本地体验**：主流本地播放器（PotPlayer、VLC、IINA）支持同名 `.srt` 文件自动挂载外挂字幕。

因此，需要在流水线中构建一套标准、精确的独立 `.srt` 字幕导出引擎。

## 架构决策 (Decision)

### 1. 独立字幕生成引擎 (`src/srt_generator.py`)
打造专用的 `SRTGenerator` 模块，严格遵循标准 SRT 规范（UTF-8 编码，`HH:MM:SS,mmm` 毫秒级时间格式）。

### 2. 契合 MoviePy 物理渲染的绝对时间轴计算算法
独立字幕的时间戳不是简单的“分镜累加”，必须精确镜像 `src/assembler.py` 中因 $0.5\text{s}$ 交叉溶解转场带来的时间轴重叠：
- **第 1 幕（$i=0$）**：
  $$T_{scene\_start}^{(0)} = 0.0\text{s}, \quad T_{audio\_start}^{(0)} = 0.10\text{s}$$
- **后续幕（$i \ge 1$）**：
  $$T_{scene\_start}^{(i)} = T_{scene\_start}^{(i-1)} + D_{scene}^{(i-1)} - 0.5\text{s}$$
  $$T_{audio\_start}^{(i)} = T_{scene\_start}^{(i)} + 0.15\text{s}$$
- **各幕字幕结束时间**：
  $$T_{audio\_end}^{(i)} = T_{audio\_start}^{(i)} + D_{audio}^{(i)}$$
通过上述算法，字幕的亮起和淡出与解说人声物理起止完全吻合，全片 6 幕无任何累积漂移。

### 3. 双模式分镜/断句支持
- **分镜级（默认）**：每幕口播文案作为一个完整字幕块（1:1 匹配画面下方胶囊文字）；
- **断句级（`--split` / `--split-srt`）**：对多短句的长口播，依据句末标点（`。`、`！`、`，`）按汉字字数占比自适应分配起止时间戳，适合剪映逐句高亮效果。

### 4. 两级全自动同步交付
- **素材阶段（`02_ai_generator.py`）**：自动落盘 `output/raw_assets/{entry_id}/subtitles.srt`；
- **合成阶段（`03_video_assembler.py`）**：自动同步并导出同名外挂字幕 `output/final_videos/{clean_name}.srt`，播放器直接自识别。
- **独立 CLI 运维**：
  ```powershell
  python -m src.srt_generator --entry-id 01_001 [--split]
  ```

## 备选方案评估 (Alternatives Considered)

### 备选方案 A：依靠第三方 Whisper 模型反向语音识别转写 SRT
- **缺点**：增加巨大的计算开销与运行依赖，且模型识别可能产生同音错别字，不如直接使用分镜原稿精准。
- **结论**：**否决（以声定景已有精准文本与时间戳，直接前向生成最可靠）**。

### 备选方案 B：仅输出分镜 JSON，由外部工具手工转换
- **缺点**：割裂工业化全自动交付流程，增加人工操作步骤。
- **结论**：**否决**。

## 实施后果与收益 (Consequences)
- 实现了软硬字幕统一，成片交付目录下 `.mp4`、`.srt`、`_cover.png` 三件套齐全；
- 极大降低了创作者在剪映/快剪辑中的二次后期门槛。
